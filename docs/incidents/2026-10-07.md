# 2026-10-07 用户空间重启与整机重启

## 15:56 用户空间重启（`pm install -r` 更新模块）

非整机断电重启。当时开机约两天，内核与 KernelSU 仍在运行。Dropbox 于 15:57:07 和 15:58:08 记录了两次 `SYSTEM_RESTART`（`isPrevious: true`）。

15:56:25 `system_server` 退出，日志位于 `/data/system/dropbox/system_server_crash@1791359785934.txt`：

1. 系统进程向自身投递广播时，接收端已失效。
2. `IIntentReceiver.performReceive` 抛出未捕获的 `DeadObjectException`，调用栈经过 `SameProcessApplicationThread.scheduleRegisteredReceiver`。
3. `RuntimeInit$KillApplicationHandler` 终止系统进程。

触发原因：模块已挂载于 `system`（用户 0），此时以 uid 2000 执行 `pm install -r` 更新 `io.github.wangxiaobo775.pluck`。安装阻塞，系统进程收到安装广播后崩溃。

新 APK 落盘后，Vector 注入时仍读取旧路径 `/data/app/~~_A0GUessG4v9npoGsoM_ag==/.../base.apk` 失败，导致新 `system_server`（pid 10253）未输出 `SysGuard: real system_server`。Vector 守护进程 `vectord` 本身运行正常（框架 2.2 / 3080 / API 102）。

结论：
- 模块加载期间禁止执行 `pm install -r`，改为通过 `deploy.sh` 原地替换 `base.apk`。
- 失效广播接收器崩溃由 `broadcast-guard` 钩子拦截。

## 17:55、18:04、18:16 三次整机重启

原因均为三星 `BootChecker` 触发 `reboot,rescueparty_by_bootchecker`：系统进程短时间内多次退出时，跳过软重启并执行整机重启。

结论：避免连续软重启。

## 18:10:44 修改 `InputMethodBindingController.mUserId` 导致系统进程崩溃

钩子将分身控制器的 `mUserId` 改为 0 后，`requestClientSessionLocked` 在主用户空的 `mCurMethod` 上调用 `getClass()` 触发空指针异常，系统进程退出（`system_server_crash@1791367844147.txt`）。

修复方案：
- 仅修改 `bindServiceAsUser` 的 `UserHandle` 参数，保留控制器原用户号。
- 主用户键盘已连接时，跳过分身重复初始化。
- `mCurMethod` 为空时跳过创建会话。

旧实现归档于 `retired/ImeBindHook.smali`，不参与编译。

## 19:31 安装应用后系统进程退出

安装应用约 90 秒后，系统进程发送安装广播时触发 `DeadObjectException` 退出，机制与 15:56 相同。19:33 执行软重启后恢复。
